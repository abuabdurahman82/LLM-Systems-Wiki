# 39 — The 20% of LLM Reliability Engineering That Explains 80% of Production Problems

`LAST_UPDATED: 2026-08-23` · Status: synthesis page (index)

If you internalise only these ten, you will correctly reason about most LLM
production incidents. Each links to its home page for depth.

**1. Measure TTFT separately from decode latency.**
TTFT and TPOT have different physics (compute/queue vs memory-bandwidth) and
different fixes — conflating them sends you to the wrong answer
([05](05-production-latency-debugging.md)).

**2. Queue growth is often more useful than raw GPU utilization.**
ρ→1 is where latency explodes, and queue depth moves before GPU% looks alarming
([08](08-queueing-theory-for-llm-sre.md)).

**3. High throughput does not guarantee good user experience.**
Lots of completed requests can coexist with everyone waiting too long
([03](03-goodput-vs-throughput.md)).

**4. Goodput matters more than peak throughput.**
Work that satisfies the SLO + quality + cost bar is what counts
([03](03-goodput-vs-throughput.md)).

**5. KV cache is a reliability resource.**
Exhaustion forces reject/evict/preempt — it's finite, contention-prone, first-class
capacity ([12](12-kv-cache-reliability.md)).

**6. Retries can make overload worse.**
A retry storm adds load to the thing that's failing and can collapse the platform
([14](14-retries-timeouts-circuit-breakers.md)).

**7. Admission control prevents catastrophic collapse.**
Bound the queue, fail fast, degrade gracefully — a platform that sheds load
survives; one that queues everything does not ([13](13-overload-protection.md)).

**8. Infrastructure health does not equal model quality.**
The GPU can be 100% healthy while the answers are broken
([24](24-quality-observability.md)).

**9. Every optimization needs regression testing.**
Latency/cost wins that silently regress quality/safety are not wins
([28](28-llm-regression-testing.md)).

**10. Model, prompt, router, RAG, and kernel changes are all production releases.**
Ship them with staging, canaries, error budgets, and rollback — not as "just a
config edit" ([25](25-model-release-engineering.md), [27](27-canary-deployment.md)).
